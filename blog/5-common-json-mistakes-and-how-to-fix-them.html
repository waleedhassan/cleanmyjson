5 Common JSON Mistakes and How to Fix Them

📅 March 29, 2026 ✍️ CleanMyJSON Team ⏱️ 8 min read
JSON Debugging Best Practices

JSON is one of the most widely used data formats in modern development, but it's also surprisingly easy to make mistakes. A single misplaced comma or missing quote can break your entire application. Understanding these common pitfalls will save you hours of debugging time.

In this guide, we'll explore the 5 most common JSON mistakes developers make and show you exactly how to fix them. Whether you're a beginner or an experienced developer, these tips will help you write cleaner, more reliable JSON.

1. Trailing Commas

Trailing commas are one of the most frequent JSON errors. While JavaScript objects allow trailing commas, standard JSON does not. This mistake often happens when you're used to writing JavaScript and forget that JSON has stricter syntax rules.

The Mistake

{
  "users": [
    {"name": "Alice", "role": "admin"},
    {"name": "Bob", "role": "editor"},
  ],
  "settings": {
    "theme": "dark",
    "notifications": true,
  }
}

The trailing commas after the last array element and last object property will cause a JSON parse error.

The Fix

{
  "users": [
    {"name": "Alice", "role": "admin"},
    {"name": "Bob", "role": "editor"}
  ],
  "settings": {
    "theme": "dark",
    "notifications": true
  }
}

2. Using Single Quotes Instead of Double Quotes

JSON strictly requires double quotes for all strings, including keys and values. Single quotes are not valid JSON syntax, even though they work in JavaScript objects.

The Mistake

{
  'name': 'John Doe',
  'email': 'john@example.com',
  'active': true
}

The Fix

{
  "name": "John Doe",
  "email": "john@example.com",
  "active": true
}

Remember: in JSON, strings must use double quotes. No exceptions.

3. Missing Quotes Around Keys

In JavaScript, you can often omit quotes around object keys. In JSON, all keys must be wrapped in double quotes. This is a strict requirement that catches many developers off guard.

The Mistake

{
  name: "Sarah",
  age: 28,
  isActive: true,
  role: admin
}

The Fix

{
  "name": "Sarah",
  "age": 28,
  "isActive": true,
  "role": "admin"
}

Notice that we also fixed admin by wrapping it in quotes—it should be a string value, not an undefined variable.

4. Using Comments in JSON

Standard JSON does not support comments. If you're coming from languages like JavaScript or Python, this limitation can be frustrating. However, including comments in your JSON will cause parse errors.

The Mistake

{
  // User configuration settings
  "config": {
    "theme": "dark", // dark or light theme
    "language": "en",
    /* Multi-line comments
       are also not allowed */
    "timezone": "UTC"
  }
}

The Fix

If you need to document your JSON, consider these alternatives:

{
  "config": {
    "_comment": "User configuration settings",
    "theme": "dark",
    "_themeDescription": "Options: dark, light, auto",
    "language": "en",
    "timezone": "UTC"
  }
}

Or use a separate documentation file alongside your JSON configuration.

5. Special Characters and Unicode Issues

Handling special characters in JSON strings requires proper escaping. Newlines, tabs, quotes, and backslashes all need to be escaped. Unicode characters also need proper encoding.

The Mistake

{
  "message": "Hello "World"",
  "path": "C:\Users\Documents",
  "multiline": "Line 1
Line 2
Line 3"
}

The Fix

{
  "message": "Hello \"World\"",
  "path": "C:\\Users\\Documents",
  "multiline": "Line 1\nLine 2\nLine 3",
  "emoji": "Hello \ud83d\ude00",
  "unicode": "Copyright \u00a9 2026"
}

Common Escape Sequences

  • \" – Double quote
  • \\ – Backslash
  • \/ – Forward slash (optional but safe)
  • \n – Newline
  • \t – Tab
  • \r – Carriage return
  • \uXXXX – Unicode character

Bonus: Unquoted String Values

Another common mistake is forgetting that all string values in JSON must be quoted. Numbers, booleans, and null don't need quotes, but strings always do.

The Mistake

{
  "status": active,
  "count": "42",
  "price": $99.99,
  "enabled": "true"
}

The Fix

{
  "status": "active",
  "count": 42,
  "price": 99.99,
  "enabled": true
}

Notice how we fixed each value type: strings get quotes, numbers stay unquoted, and boolean values are literal true/false without quotes.

Follow these tips to write error-free JSON:
